Scheduled Task Persistence — Detection Engineering & SOC Investigation

Investigation path
01 // Execute

Ran Atomic Red Team T1053.005-2 to create a scheduled task invoking cmd.exe.

02 // Verify

Confirmed the task executed, then checked whether Windows produced the telemetry required for detection.

03 // Find gap

Event ID 4698 was initially absent. The issue was audit configuration, not the attack simulation.

04 // Remediate

Enabled “Other Object Access Events” auditing and verified Event ID 4698 in the Security log.

05 // Detect

Wazuh rule 60228 fired; custom rule 100002 escalated suspicious cmd.exe task content to level 12.

Detection decision

The built-in Wazuh rule 60228 treats scheduled-task creation as a level-4 informational event. That is useful telemetry, but it does not distinguish routine administrative tasks from a task carrying suspicious command execution. I chained a custom rule to the baseline detection and inspected the task payload for cmd.exe, raising the event to level 12 and mapping it precisely to T1053.005.

Custom detection logic 
<rule id="100002" level="12">
  <if_sid>60228</if_sid>
  <field name="win.eventdata.taskContent">cmd.exe</field>
  <description>ATT&CK T1053.005: Suspicious scheduled task spawning cmd.exe</description>
  <mitre><id>T1053.005</id></mitre>
</rule>
What failed / what changed
Telemetry blind spot

The first test did not generate Event ID 4698. I traced the miss to Windows audit policy, enabled the required subcategory, verified the event locally, and reran the simulation.

Lab reliability

PowerShell execution policy and Defender quarantine interfered with Atomic Red Team setup. I corrected the isolated lab configuration rather than treating tool execution as proof that detection was working.

SIEM operations

Wazuh storage pressure exposed an infrastructure issue. Vulnerability-detection data was disabled for this focused lab after diagnosing the disk constraint.

Analyst takeaway

A rule cannot detect telemetry the endpoint never records. Sensor and audit-policy validation belongs inside the detection-engineering workflow.
